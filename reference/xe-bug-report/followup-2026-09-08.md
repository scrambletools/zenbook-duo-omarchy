Follow-up after more testing. Two corrections to the original report.

**1. Docking is not the trigger.** A boot with the detachable keyboard never on the laptop (disk password typed on an external USB keyboard, keyboard docked only after login) still ended with PHY B unusable. In that state the first error already appears at boot, about two seconds after the main system starts (Plymouth re-attaching to DRM):

```
xe … *ERROR* AUX B/DDI B/PHY B: Failed to write aux backlight level: -110
xe … vblank wait timed out on crtc 1
xe … *ERROR* [CRTC:270:pipe B] flip_done timed out
xe … pipe_off wait timed out
xe … *ERROR* Failed to bring PHY B to idle.
xe … PHY B failed to change powerdown state
```

Every later enable of eDP-2 then fails with the refclk / link training sequence from the report.

**2. The bad state persists across a warm reboot and across a quick power-off** (charger connected, back on within a minute). Each such boot showed the errors above, while the firmware still lit the panel normally at the unlock prompt. It is cleared by a full power reset (shutdown, charger unplugged, power button held ~15 s, a minute off) and by loading firmware setup defaults. After either, the same kernel and parameters boot clean and eDP-2 disable/enable cycles work.

Still true: with the keyboard docked at power-on the firmware does not light the covered panel, and the first enable of eDP-2 then fails even after a healthy previous boot.

Ruled out: `xe.enable_dc=0`, `xe.enable_panel_replay=0` (needed for an unrelated boot hang, no effect here), `video=eDP-2:d`, AC vs battery.

Kernel 7.1.9-arch1-2 throughout. Happy to provide a `drm.debug=0x1e` log of a wedged boot on request.
